## Create a project

Use Node.js 22 or newer, git and pnpm. The kit pins pnpm 12.14.0; CI uses Node.js 26.

```bash
npm create nuxt-saas@latest my-app
```

The terminal picker offers optional modules. Required modules come along automatically, and base is
always included. A selected module lives in `layers/<id>/`; unselected layers are not copied.
To select modules without prompts:

```bash
npm create nuxt-saas@latest my-app -- --yes --modules auth,content
```

`--yes` without `--modules` creates **base only**. Use `content` if you want these documentation
pages and the blog, `auth` for sign-in/account pages, and `pwa` for the service worker and install UI.
Init needs an empty target and initializes git unless you pass `--no-git` or are already in a repository.

## Configure and run

```bash
cd my-app
pnpm install
cp .env.example .env
```

Fill the environment values for your selected modules. If your selection includes `database`
(including through `auth`), generate migrations for those schemas:

```bash
pnpm db:generate
```

Kit migrations are never copied; do not create or edit migration SQL/snapshots by hand.

```bash
pnpm dev
```

Open `http://localhost:3000`. Update `site.config.ts` with your site's details. With `content`
installed, documentation configuration is in `layers/content/docs.config.ts` and Markdown lives in
root `content/`.

## Add, remove and upgrade

Keep `.nuxt-saas.json` in version control. It records the template, full kit commit, selected module
IDs, project identity and unresolved conflicts. Run subcommands before their flags:

```bash
pnpm dlx create-nuxt-saas@latest modules
pnpm dlx create-nuxt-saas@latest add pwa --check
pnpm dlx create-nuxt-saas@latest add pwa
pnpm dlx create-nuxt-saas@latest remove pwa
pnpm dlx create-nuxt-saas@latest upgrade --check
pnpm dlx create-nuxt-saas@latest upgrade
```

Add/remove use the recorded kit commit; upgrade resolves a new target commit. Removal is refused
when a remaining module requires what you are removing. `--dir path` selects another project.
`--check` previews without writing, even on a dirty tree. Applying requires a clean git tree unless
`--force` is passed. Follow the printed dependency, environment and `pnpm db:generate` steps.

Changes to your files are three-way merged. Overlapping text edits write conflict markers, record
paths and exit 1; the recorded commit/module selection advances to the target. Resolve the listed
files and commit your resolution before the next applied command. It refuses while opening conflict
markers remain and clears the conflict list on the next applied transition; there is no continue
command.

Existing environment files (except `.env.example`), migrations, root lockfiles and `content/**` are
protected. New protected files can be introduced with a module or upstream addition, but an existing
protected file you deleted stays deleted on upgrade.

## Projects created with CLI 2.x

3.0.0 does not migrate the old `.nuxt-saas/manifest.json`. It stops with:

> This project was created by create-nuxt-saas 2.x, which this version cannot manage. Generate a new project with `npm create nuxt-saas@latest` and move your code across.

Regenerate rather than renaming the old manifest. `status` and `diff` are no longer commands; use
`upgrade --check`. See the [CLI README](https://github.com/No-Name-Studio-VN/Nuxt-Starter-Kit/tree/main/packages/create-nuxt-saas#readme)
for all flags, local-kit development and module authoring. Cloning the repository instead of using
the CLI gives you the full kit with every layer.
